シリアル通信（Serial Communication）とは、**データを1ビットずつ、順番に1本（または数本）の信号線で送受信する通信方式**です。

---

## パラレル通信との違い

対比すると理解しやすいです。

| 方式 | 配線 | データの送り方 | 特徴 |
|------|------|----------------|------|
| **パラレル通信** | 8本・16本・32本など | 複数ビットを同時に送る | 速いが配線が多く、長距離でノイズに弱い |
| **シリアル通信** | 1本〜3本程度 | 1ビットずつ順番に送る | 配線が少なく、長距離・ノイズに強い |

以前はプリンタのCentronicsケーブルなどがパラレル通信でしたが、現在はUSBやEthernetなど、ほとんどがシリアル通信ベースです。

---

## 基本的な仕組み

### フレーム構成（1回の送信単位）
シリアル通信では、以下の順序でデータを送ります。

```
[アイドル:HIGH] [開始ビット:LOW] [データビット(8bit)] [パリティ(任意)] [停止ビット:HIGH]
```

- **開始ビット**: 通信開始の合図（LOWに落とす）
- **データビット**: 実際のデータ（通常8bit = 1バイト）
- **パリティビット**: エラーチェック用（偶数/奇数パリティ、またはなし）
- **停止ビット**: 通信終了の合図（HIGHに戻す）

### ビットレート（ボーレート）
1秒間に何ビット送れるかを示す単位です。送受信双方が**同じボーレートに設定**されている必要があります。

| ボーレート | 1バイトあたりの時間（概算） |
|------------|---------------------------|
| 9600 bps | 約1ms |
| 115200 bps | 約87μs |
| 921600 bps | 約11μs |
| 1 Mbps (1000000) | 約10μs |

## 主な種類

### 1. UART（TTLレベル）
マイコン同士を基板上で接続する際に最も使われる方式です。

- **配線**: TX（送信）・RX（受信）・GND（共通接地）の最低3本
- **電圧レベル**: 3.3Vまたは5V（LVTTL / TTL）
- **距離**: 数cm〜数十cm（基板間・ケース内）
- **特徴**: 非同期（クロック線なし）、安価、設定が簡単

```
Raspberry Pi(TX) ────→(RX) Teensy
Raspberry Pi(RX) ←────(TX) Teensy
            GND ─────── GND
```

### 2. USBシリアル（USB CDC）
USBケーブル1本でシリアル通信を行う方式です。

- **配線**: USBケーブル1本
- **特徴**: PCやRaspberry Piが認識しやすい、ドライバ不要（多くの場合）
- **実例**: ArduinoやTeensyをPCにUSB接続してシリアルモニタで通信

### 3. RS-232
古いPCにあった9ピン（D-Sub 9pin）コネクタで使われる規格です。

- **電圧レベル**: ±3V〜±15V（TTLとは互換なし、変換ICが必要）
- **距離**: 最大15m程度
- **用途**: 産業機器、ネットワーク機器のコンソールポートなど

### 4. RS-485
産業用機器で広く使われる、ノイズに強い規格です。

- **配線**: A・Bの差動2本（+ GND）※全双工版もあり
- **特徴**: ノイズに非常に強い、最長1200m、マルチドロップ（複数機器を同じ線に接続）可能
- **用途**: 工場のセンサーネットワーク、モータドライバ、太陽光発電のパワコンなど

---

## 同期式と非同期式

| 方式 | クロック線 | 特徴 |
|------|-----------|------|
| **非同期（Asynchronous）** | なし（UARTなど） | ボーレートでタイミングを合わせる。配線が少ない |
| **同期式（Synchronous）** | あり（SPI、I2Cなど） | クロックに合わせて送受信。高速・安定 |

SPIやI2Cも広義にはシリアル通信ですが、通常「シリアル通信」と言えば**非同期のUART**を指すことが多いです。

## 実際の使い方の例

### Python（Raspberry Pi）での受信
```python
import serial

# /dev/ttyUSB0 または /dev/ttyACM0 に接続、115200bps
ser = serial.Serial('/dev/ttyUSB0', 115200, timeout=1)

# 送信
ser.write(b'Hello Teensy\n')

# 受信
line = ser.readline()
print(line.decode('utf-8').strip())
```

### Arduino/Teensyでの受信
```cpp
void setup() {
    Serial.begin(115200);
}

void loop() {
    if (Serial.available()) {
        String msg = Serial.readStringUntil('\n');
        Serial.print("Received: ");
        Serial.println(msg);
    }
}
```

## まとめ

シリアル通信とは、**データを1ビットずつ順番に送る通信方式**です。

- **メリット**: 配線が少ない、長距離対応可能、安価で実装が簡単
- **デメリット**: パラレルより遅い（ただし現代の高速シリアルは十分速い）
- **代表的な規格**: UART（TTL）、USBシリアル、RS-232、RS-485

Raspberry Piとマイコン（Teensyなど）を接続する場合、**USBシリアル（CDC）**または**UART（TTL）**が最も一般的で、設定も比較的簡単です。


シリアル通信は1本の線でデータを1bitずつ送信する通信方式。
長距離可能、ノイズに強い、配線が少なくてもよいというメリットがある。


TTLは **Transistor-Transistor Logic** の略で、もともとはトランジスタを使った**デジタル回路の設計方式**の名前です。

現在では、シリアル通信の文脈では **「低電圧のデジタル信号レベル」** を指す言葉として使われます。簡単に言えば、**マイコンや基板上で使われる 3.3V または 5V の ON/OFF 信号**のことです。

---

## 電圧レベルの具体的な意味

TTLレベルでは、電圧の高さで「0」と「1」を表現します。

| 論理値 | 電圧範囲（5V TTL） | 電圧範囲（3.3V LVTTL） |
|--------|-------------------|----------------------|
| **1（HIGH）** | 2.0V 〜 5.0V | 2.0V 〜 3.3V |
| **0（LOW）** | 0V 〜 0.8V | 0V 〜 0.8V |

- **5V TTL**: Arduino Uno など古い/標準的なマイコンで使われる
- **3.3V LVTTL**（Low Voltage TTL）: Raspberry Pi、Teensy 4.1、ESP32 など最近のマイコンで使われる

---

## なぜ「TTL」という言葉が出てくるのか

マイコン同士を直接配線で繋ぐUART通信では、以下のように**電圧そのものをHIGH/LOWで送ります**。

```
3.3V ───┐         ┌─── 3.3V（HIGHとして認識）
        │         │
0V  ────┴─────────┴──── 0V（LOWとして認識）
```

これを **「TTLレベルのシリアル通信」** と呼びます。基板上のチップ同士の会話に使われる、身内向けの信号です。

---

## RS-232 との決定的な違い

TTLとよく比較されるのが RS-232 です。

| 項目 | TTL（UART） | RS-232 |
|------|-------------|--------|
| **HIGH（1）の電圧** | 3.3V または 5V | **-3V 〜 -15V**（マイナス！） |
| **LOW（0）の電圧** | 0V | **+3V 〜 +15V**（プラス） |
| **用途** | 基板上・ケース内のチップ同士 | PCと周辺機器、長距離通信 |
| **距離** | 数cm〜数十cm | 最長15m程度 |

RS-232は**マイナス電圧をHIGHとする**という、TTLとは逆でしかも高電圧な仕様です。そのため、**TTLのマイコンにRS-232信号を直接入れると、高電圧で壊れる**可能性があります。MAX232などの変換ICが必要になります。

---

## 重要な注意点：電圧レベルの不一致

これが実際の制作で最も気をつけるべき点です。

| 組み合わせ | 結果 |
|-----------|------|
| **3.3V機器 → 3.3V機器** | そのまま接続OK |
| **5V機器 → 3.3V機器** | **3.3V機器が破損する可能性あり**（過電圧） |
| **3.3V機器 → 5V機器** | 5V機器が認識しない場合あり（電圧が低いため） |

### 例：Raspberry Pi と Arduino Uno を繋ぐ場合
- Raspberry Pi の GPIO: **3.3V LVTTL**
- Arduino Uno の GPIO: **5V TTL**

ArduinoのTX（5V）をRaspberry PiのRX（3.3V）に直接繋ぐと、**Raspberry Piが故障する**ことがあります。対策として以下があります。

- **レベル変換回路（ロジックレベルシフタ）** を使う（例: BSS138モジュール、¥100〜300）
- **電圧分圧抵抗** で5Vを3.3Vに落とす（簡易的）
- **USBシリアル変換ケーブル（3.3V版）** を使う

---

## まとめ

- **TTL**: マイコンやデジタルICが基板上で使う **3.3V/5V の HIGH/LOW 信号**
- **TTLシリアル（UART）**: その電圧レベルで行う非同期シリアル通信
- **注意**: 3.3V機器と5V機器を直接繋ぐと**壊れる**ことがあるので、レベルシフタが必要

Raspberry PiとTeensy 4.1はどちらも **3.3V LVTTL** なので、UARTで直接（TX-RXクロス接続、GND共通）繋いでも問題ありません。
