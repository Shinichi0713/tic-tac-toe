Raspberry Piを制御系の中核に据える場合、**「上位計算をPi、リアルタイム制御を専用回路に任せる階層構成」**が最も現実的で安定します。Pi単体でのLinuxリアルタイム制御は1kHz以上を安定して回すのが難しいためです。

以下に、用途別の2つの構成案を示します。

---

## 構成案A：小型実験機・DIY向け（最も安価）

ステッピングモータを使い、Piから直接制御します。精度は中程度ですが、コストが抑えられます。

### ハードウェア構成

| 部位 | 部品例 |
|------|--------|
| **コントローラ** | Raspberry Pi 4（8GB推奨）または Pi 5 |
| **GPIO拡張** | CNC Shield v3.0（Arduino Uno形状）+ Raspberry Pi GPIO接続アダプタ、または専用HAT |
| **モータ** | NEMA23 ステッピングモータ ×6（保持トルク 1.26Nm程度） |
| **ドライバ** | TB6600 または DM556 ステッパードライバ ×6 |
| **電源** | DC 24V 15A スイッチング電源（モータ用）+ DC 5V 3A（Pi用） |
| **通信** | USB（キーボード・Wi-Fi設定用）、GPIOからのパルス/ディレクション信号 |
| **センサ** | リミットスイッチ ×12（各脚上下）、オプションでロータリエンコーダ |
| **安全** | 緊急停止スイッチ → リレーでモータ電源遮断（Pi経由ではなくハード回路） |

### 接続イメージ

```
Raspberry Pi
   └─ GPIO ─┬─ PUL/DIR信号 ─→ ステッパードライバ×6 ─→ ステッピングモータ×6
            ├─ リミットスイッチ入力（×12）
            └─ E-Stop入力（ハード回路と並列監視）
```

### ソフトウェア構成

- **OS**: Raspberry Pi OS（64bit）
- **IK・軌道生成**: Python（NumPy）で実装
- **GPIO制御**: `pigpio` ライブラリ（ハードウェアPWMが使えて比較的安定）
- **UI**: FlaskまたはStreamlitでWebブラウザから姿勢指令
- **通信**: オプションでMQTTまたはWebSocketで外部PCから指令受信

### 制御ループ

1. Pythonで目標姿勢から6脚の目標長さを計算（IK）
2. 現在長から差分を求め、各モータのパルス数に変換
3. `pigpio`で各軸に非同期パルス列を出力（S字加減速はソフトウェアで補間）
4. リミットスイッチ入力をポーリングまたは割り込みで監視

### 課題
- 6軸同時に滑らかな補間をPi単体で回すのは負荷が高い
- ステッピングモータは開ループのため、負荷変動で**失調（ずれ）**するリスクあり
- 標準Linuxカーネルではタイムジッターが発生し、動作がわずかにガタつく可能性あり

## 構成案B：中級・高精度向け（推奨）

Piを「指令生成・通信・UI」の上位機として使い、**リアルタイム制御は専用マイコンまたはモーションコントローラ**に任せます。

### ハードウェア構成

| 部位 | 部品例 |
|------|--------|
| **上位コントローラ** | Raspberry Pi 4/5（IK計算、Web UI、データロギング） |
| **下位コントローラ** | **Arduino Mega** + **RAMPS 1.4**（Marlinファームウェア改造）、または **Teensy 4.1**、**ESP32-S3** |
| **モータ** | 閉ループステッピングモータ（エンコーダ付き）×6、または低価格ACサーボ |
| **ドライバ** | 閉ループステッパードライバ ×6、またはサーボドライバ |
| **通信Pi↔下位** | USBシリアル、UART、またはCANバス（ESP32の場合） |
| **センサ** | リミットスイッチ、オプションでムーバー側IMU（MPU6050/BNO055、I2C接続） |
| **電源** | DC 24V/36V 大容量（モータ用）、DC 5V（Pi・マイコン用） |
| **安全** | 独立したE-Stopリレー回路 |

### 接続イメージ

```
Raspberry Pi（上位）
   ├─ USB ─→ Arduino Mega / Teensy 4.1（下位リアルタイム制御）
   │            └─ パルス/アナログ信号 ─→ モータドライバ×6 ─→ モータ×6
   ├─ I2C ─→ BNO055（ムーバーIMU、オプション）
   └─ Wi-Fi/Ethernet ─→ PCやジョイパッドから指令受信
```

### ソフトウェア構成

| 層 | 役割 | 技術 |
|----|------|------|
| **上位（Pi）** | IK計算、軌道計画、Web UI、ログ保存 | Python + NumPy + Flask/Streamlit |
| **通信** | 目標脚長または目標姿勢の送信 | USBシリアル（JSONまたはバイナリプロトコル）、ROS |
| **下位（マイコン）** | 1kHz〜10kHzの位置制御、補間、E-Stop処理 | Arduino（C++）、FreeRTOS、またはPlatformIO |

### 制御フロー

```
PC/ジョイパッド
   ↓ （目標姿勢を送信）
Raspberry Pi
   → IK計算 → 6軸の目標脚長・目標速度を生成
   → 10ms周期で下位マイコンにパケット送信（「脚1: 150.2mm, 速度: 20mm/s」など）
Arduino/Teensy
   → 受信した目標値に基づき、各軸のPID制御・S字加減速を1kHzで実行
   → リミットスイッチ・E-Stopを直接監視し、異常時は即停止
```

## 構成案C：LinuxCNCを使う本格派

Pi上で**LinuxCNC**（実機制御用のオープンソースCNCソフト）を動かし、専用の**Mesaインターフェースボード**を使ってGPIOをリアルタイム拡張します。

| 部位 | 部品 |
|------|------|
| **Pi** | Raspberry Pi 4 + Raspberry Pi OS with LinuxCNC |
| **I/Oボード** | Mesa Ethernet/SPiインターフェース（例: 7C81などPi用HAT） |
| **モータ** | サーボまたはステッピング |
| **特徴** | Gコードで動作可能、産業級の補間制御が使える |

ただし、スチュアートプラットフォームのIKをLinuxCNCに組み込むには**HALコンポーネントのカスタマイズ**が必要で、ハードルが高いです。

## Raspberry Pi構成の選び方

| 目的 | 推奨構成 |
|------|----------|
| **とにかく安く試したい** | 構成A（Pi + TB6600 + ステッピング） |
| **ある程度の精度・滑らかさが欲しい** | **構成B（Pi + Teensy 4.1 + 閉ループステッパー）** ← 最もバランスが良い |
| **産業級の信頼性が必要** | 構成C（LinuxCNC + Mesa）またはPiを諦めてTwinCAT |

---

## 実装上の注意点（Pi特有）

1. **電源の分離**: Piの5V系とモータの24V系は完全に分離。モータのノイズでPiがリセットするため、フォトカプラで絶縁することを推奨します。
2. **リアルタイム性**: PiのGPIOから6軸同時に滑らかなパルスを出すのは限界があります。下位マイコンを挟む構成Bが現実的です。
3. **熱対策**: Pi 4/5は負荷時に発熱します。ヒートシンクまたはファンを必ず装着してください。
4. **SDカードの寿命**: 頻繁なログ書き込みでSDカードが破損するため、USB SSDブートまたは工業用microSD（高耐久）を使用してください。

| 部品 | 通信 | 価格帯 | 特徴 |

### C. 脚長フィードバック（モータ軸・リニア位置）

| 方式 | 部品例 | 備考 |
|------|--------|------|
| **モータエンコーダ（ロータリ）** | 閉ループステッパー内蔵（1000P/R） | ねじリード換算でリニア位置を推定。最も一般的 |


## 5. 通信プロトコルの具体例（Pi ↔ Teensy）

JSON形式でテキスト通信するのがデバッグしやすく推奨です。921600bpsなら1ms未満で送受信可能です。

```json
// Pi → Teensy（目標姿勢、10ms周期）
{"cmd":"move","x":0.0,"y":0.0,"z":120.0,"roll":0.0,"pitch":0.05,"yaw":0.0}

// Teensy → Pi（状態フィードバック、10ms周期）
{"leg":[120.1,119.8,120.3,120.0,119.9,120.2],"imu":{"roll":0.01,"pitch":0.06},"alarm":0}
```

本番運用時は **MessagePack（バイナリJSON）** や **CBOR** に切り替えるとオーバーヘッドが減ります。

## 6. 選定のポイントまとめ

- **通信**: 実験室ならUSBシリアル（921600bps）、工場・ノイズ環境ならCANバス
- **IMU**: 楽に実装するならBNO055（I2C）、性能重視ならICM-20948（SPI）
- **リミット**: ホールセンサ（A3144E）が無接点で長寿命でコスパ良し
- **フィードバック**: 閉ループステッパーのエンコーダをTeensyのQuadDecoderで読むのが標準的
- **安全**: E-Stopは**絶対に**ソフトウェアを介さないリレー回路で電源を遮断

この構成で、Teensy 4.1は1kHz〜4kHzの位置制御ループを6軸分余裕で回せます。Raspberry PiはPythonでIKと軌道生成を担当し、10ms周期で目標値をTeensyに渡す形が最も実現性が高いです。


## TTL

TTLはトランジスタを用いたデジタル回路の設計方式の名前。
現在ではシリアル通信の文脈では低電圧のデジタル信号レベルを示す言葉。
マイコンや基盤で使われる3.3 or 5Vのデジタル信号のこと。

実はどちらかというと3.3V系の方が新しいマイコン。

3.3V系は2V以上でHigh
5V系も2V以上でHigh

RS-232はマイナス電圧をHighとする。
そのため、ラズパイとRS-232を接続すると高圧で壊れる可能性がある。

## バッテリ系

バッテリでスチュアートプラットフォームやRaspberry Pi系の制御システムを駆動する場合、**「電圧・容量・安全」の3つ**が最重要です。以下に、構築時に注意すべき具体的なポイントをまとめます。

---

## 1. バッテリの選定（化学種の比較）

用途に応じて選びます。モータを動かす場合は**放電電流（Cレート）**が特に重要です。

| 種類 | 公称電圧 | 特徴 | 向いている用途 |
|------|----------|------|----------------|
| **鉛蓄電池（SLA）** | 12V | 安価、重い、低Cレート、耐過放電がやや弱い | 据え置き実験、重量が問題ない場合 |
| **Li-ion 18650/21700** | 3.7V/セル | 容量密度が高い、保護回路必須、熱に注意 | 軽量・長時間駆動が必要な場合 |
| **LiPo（リポ）** | 3.7V/セル | 非常に高い放電率（高C）、軽い、扱いが繊細 | 高トルク・高速モータ、ドローン系 |
| **LiFePO4** | 3.2V/セル | 安全性が高い、長寿命、重いめ | 産業用、車載、安全重視のシステム |

### モータ駆動の場合
ステッピングモータやサーボを6本動かすと、**起動時（突入電流）に数十Aが一瞬流れる**ことがあります。

- **LiPo** または **LiFePO4**（高率放電タイプ）を推奨
- 鉛蓄電池でも可ですが、**20Ah以上**の容量が必要になることが多いです

---

## 2. 必要電圧の設計とセル構成

モータドライバやRaspberry Piの入力電圧要件を満たす必要があります。

### 24Vシステムを作る場合の例
| バッテリ種 | セル構成 | 満充電電圧 | 公称電圧 |
|-----------|----------|------------|----------|
| 鉛蓄電池 | 2個直列（12V×2） | 約13.8V×2 = **27.6V** | 24V |
| LiPo | 6S（3.7V×6） | 4.2V×6 = **25.2V** | 22.2V |
| LiFePO4 | 8S（3.2V×8） | 3.6V×8 = **28.8V** | 25.6V |

### 注意点
- **満充電時の電圧**が、モータドライバやDC-DCコンバータの**最大入力電圧を超えない**ことを確認してください。例えば、入力上限30Vのドライバに8S LiFePO4（28.8V）はギリギリです。
- **放電終止電圧**を下回らないよう、BMSまたは電圧モニタで保護してください。

---

## 3. BMS（Battery Management System）は必須

リチウム系バッテリ（Li-ion、LiPo、LiFePO4）には**絶対にBMSを入れてください**。入れない場合、火災や破裂のリスクがあります。

BMSが行う保護：
- **過充電保護**（セル電圧上限を超えた充電を遮断）
- **過放電保護**（セル電圧下限を下回った放電を遮断）
- **過電流保護**（短絡や過負荷時に遮断）
- **セルバランシング**（直列セル間の電圧差を均等化）

### 選定のポイント
- **直列数（S）**と**並列数（P）**に合ったBMSを選ぶ
- **放電電流定格**は、モータの最大消費電流の**1.5倍〜2倍**を見積もる
  - 例: モータ系でピーク20Aなら、BMSは30A〜40A定格を選ぶ

---

## 4. 充電システムの設計

バッテリを構築するなら、充電器も同時に設計します。

| 項目 | 注意点 |
|------|--------|
| **充電電圧** | バッテリの種類・直列数に合わせた専用充電器を使う。汎用アダプタでは危険 |
| **充電電流** | 容量の0.3C〜0.5C（例: 10Ahなら3A〜5A）が標準的。急ぎすぎない |
| **温度監視** | 0℃以下でのLi-ion/LiPo充電は**絶対禁止**（リチウム析出→内部短絡→火災） |
| **充電・放電の分離** | システムを動かしながら充電したい場合は、**チャージャと負荷の接続方法**をBMS仕様で確認する |

---

## 5. Raspberry Pi・マイコンへの電源供給

バッテリ電圧（12V/24V）をそのままマイコンに入れると破損します。以下のように降圧します。

```
バッテリ（24V）→ DC-DC降圧モジュール（Buckコンバータ）→ 5V/3A（Pi用）
```

### 推奨部品
| 用途 | モジュール例 | 備考 |
|------|-------------|------|
| **Pi 4/5用** | LM2596系（3A）や、より高効率のMP1584ENモジュール | 5V/3A〜5Aを安定供給できるもの |
| **Teensy/ESP32用** | 同上、または3.3Vレギュレータ併用 | Teensy 4.1はUSB給電でも動くが、ノイズ対策で独立5V供給が望ましい |
| **モータと同じ電源からの分岐** | **絶対に共通GNDは取る**が、Piの5Vラインにはノイズフィルタ（フェライトコア）を入れる | モータのノイズでPiがリセットするのを防ぐ |

### 重要
- **DC-DCはモータ電源とは別にする**か、十分な容量のコンデンサ（数百〜数千μF）を入れてノイズを吸収してください。
- Raspberry Piの電源は**電圧降下に弱い**です。ケーブルが細いと再起動します。

---

## 6. 配線・保護回路の注意点

### 配線太さ（AWG）
| 電流 | 推奨AWG | 用途 |
|------|---------|------|
| 〜5A | AWG20〜22 | センサ、マイコン、信号系 |
| 〜15A | AWG16〜18 | 中型モータ1〜2本 |
| 〜30A | AWG12〜14 | モータ系全般、メイン電源 |

### 保護部品
- **ヒューズまたはサーキットブレーカ**: メイン電源ラインに必ず挿入
- **逆接続保護ダイオード/MOSFET**: バッテリを逆に繋いだ時の保護
- **スイッチ**: メインスイッチは**バッテリのプラス側**に入れる
- **E-Stop回路**: モータ電源を直接遮断できるリレー回路（バッテリ系でも必須）

---

## 7. モータ負荷特有の注意点

バッテリはACアダプタとは異なり、**内部抵抗がある**ため大電流を出すと電圧が下がります。

- **突入電流**: モータ起動時に定格の3〜5倍の電流が流れるため、電圧が一瞬大きく下がる（サージ）。これでPiがリセットすることがあります。
  - 対策: バッテリ端子に大容量電解コンデンサ（数百〜数千μF、電圧定格十分なもの）を並列に入れる
- **回生電流**: モータが減速すると、発電機になりバッテリに電流を返すことがあります。
  - 対策: バッテリとは別に**回生用ダンピング抵抗**や、回生を吸収できる充電池を使用

---

## 8. 熱管理と物理的設置

- **リチウム系バッテリ**は45℃以上での連続使用で劣化が激しくなります。金属筐体への直付けや密閉筐体での使用は避け、放熱スペースを確保してください。
- **振動対策**: スチュアートプラットフォームは振動します。バッテリを**スポンジやゴムマウントで固定**し、配線の引き回しに遊び（余長）を持たせてハーネスが切れないようにしてください。
- **防水・防塵**: 実機で屋外や工場を想定するなら、IPレベルを考慮してください。

---

## まとめ：バッテリ系構築のチェックリスト

1. **化学種選定**: 高電流が必要ならLiPoまたはLiFePO4（高率放電型）
2. **BMS**: 直列数・電流定格に合ったものを必ず装着
3. **電圧設計**: 満充電時の電圧が機器の上限を超えないか確認
4. **充電器**: バッテリ専用のものを使用。温度管理を徹底
5. **降圧回路**: Pi・マイコンにはDC-DCで5V/3.3Vを生成。ノイズフィルタ必須
6. **保護**: ヒューズ、逆接続防止、E-Stopリレーをメイン電源に配置
7. **熱・振動**: 放熱スペースと防振マウントを確保

具体的なモータの消費電力や、想定動作時間が決まっていれば、バッテリ容量（Ah）やBMSの定格をより具体的に計算できます。


## 電圧低下の理由

バッテリは理想電源＋内部抵抗

バッテリの内部抵抗と電圧低下について、順を追って説明します。

---

## 1. バッテリは「理想電源 + 内部抵抗」の等価回路

バッテリは一見「24Vを出す箱」に見えますが、実際には**内部に目に見えない抵抗が存在**します。

```
【理想電源】        【内部抵抗: Ri】
   24V ──[===]──────[Ri: 0.1Ω]──────→ 端子電圧（実際の出力）
                               │
                               └─→ モータなどの負荷
```

端子から測った電圧は、**内部抵抗の後**の電圧です。

---

## 2. オームの法則で電圧が下がる仕組み

電流が流れると、内部抵抗の両端に電圧降下（`V = I × R`）が生じます。

### 具体例：24Vバッテリ（内部抵抗 0.1Ω）の場合

| 負荷電流 | 内部抵抗での電圧降下 | 端子電圧（実際の出力） |
|----------|---------------------|----------------------|
| **1A**（待機時） | 1A × 0.1Ω = **0.1V** | 24V − 0.1V = **23.9V** |
| **5A**（軽負荷） | 5A × 0.1Ω = **0.5V** | 24V − 0.5V = **23.5V** |
| **20A**（モータ駆動） | 20A × 0.1Ω = **2.0V** | 24V − 2.0V = **22.0V** |
| **50A**（突入電流） | 50A × 0.1Ω = **5.0V** | 24V − 5.0V = **19.0V** |

**電流が大きくなるほど、内部抵抗での損失が大きくなり、端子電圧が大きく下がります。**

---

## 3. なぜモータ起動時に「突入電流」が流れるのか

モータ（特にDCモータやステッピングモータ）は、回転すると**逆起電力（バックEMF）**を発生させます。逆起電力は電源の電圧と逆向きに働き、回転が速くなるほど大きくなります。

### 回転中の等価回路
```
電源電圧 = 逆起電力 + 回線抵抗×電流
```

回転が速いほど逆起電力が大きくなり、流れる電流は小さくなります。

### 起動時（停止状態）
- 回転速度 = **ゼロ**
- 逆起電力 = **ゼロ**
- 流れる電流は、モータの**純粋な回線抵抗のみ**で決まる
- 回線抵抗は非常に小さい（例: 0.5Ω〜2Ω）ため、**起動時にだけ非常に大きな電流が流れる**

### 具体例
定格5Aのモータが、起動時に一瞬だけ**20A〜30A**流れるのはこのためです。

---

## 4. バッテリ系で何が起きるか

スチュアートプラットフォームのように**6本のモータを同時起動**すると、以下の現象が起きます。

```
バッテリ（24V、内部抵抗0.1Ω）
   │
   ├─→ モータ1: 起動時20A
   ├─→ モータ2: 起動時20A
   ├─→ モータ3: 起動時20A
   ...（合計 100A以上が一瞬流れる）
```

### 電圧降下の計算例
- 合計電流: **100A**（6軸同時起動の瞬間）
- 内部抵抗: **0.1Ω**
- 電圧降下: 100A × 0.1Ω = **10V**
- 端子電圧: 24V − 10V = **14V**

**24V系統が一瞬14Vまで落ち込みます。** この電圧降下が、同じ電源から降圧して5Vを作っているRaspberry Piに波及し、**Piの5Vレギュレータが機能停止 → Piがリセット**するのです。

---

## 5. 対策の原理

### A. 大容量コンデンサ（バンクコンデンサ）
コンデンサは**一時的に電荷を蓄え、急な電流需要に瞬時に応える**ことができます。

```
バッテリ ───┬──[コンデンサ: 1000μF〜10000μF]──┬──→ Pi用DC-DC
            │                                  │
            └──────────────┬───────────────────┘
                           │
                        モータドライバ
```

- モータ起動時の急な電流需要は、コンデンサが先に補填する
- バッテリには急激な電流変化が伝わりにくくなり、電圧降下が緩和される
- コンデンサの電圧定格は、使用電圧の**1.5倍以上**（24V系なら50V〜63V定格）を選ぶ

### B. 電源の分離（推奨）
根本的な対策は、**モータ用電源とPi用電源を分離する**ことです。

```
【モータ系】
バッテリ（24V）──→ モータドライバ×6

【制御系】
別バッテリ（12V/5V）または独立DC-DC──→ Raspberry Pi / Teensy
（モータ電源とは別系統、GNDのみ共通）
```

これにより、モータの突入電流がPiの電源に影響を与えなくなります。

### C. バッテリの内部抵抗を下げる
- **並列接続**: 同種のバッテリを並列にすると、内部抵抗は半分になります（2個並列で0.1Ω→0.05Ω）
- **容量の大きなバッテリ**: 一般的に容量が大きいほど内部抵抗は小さい（20Ahより100Ahの方がピーク電流に強い）

---

## まとめ

1. **バッテリは内部抵抗を持つ**：電流が流れると `V = I × R` で電圧が下がる
2. **モータ起動時は逆起電力がゼロ**：通常時の3〜5倍の電流が一瞬流れる（突入電流）
3. **6軸同時起動で電圧が大きく落ちる**：Piの5Vレギュレータが止まり、リセットする
4. **対策**：大容量コンデンサによる緩衝、またはモータ電源と制御電源の分離が最も効果的

この現象は「**電源のディップ（電圧低下）**」や「**ブラウンアウト**」と呼ばれ、バッテリ駆動のモータ制御で最も遭遇しやすいトラブルの一つです。
