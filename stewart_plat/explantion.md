Raspberry Piを制御系の中核に据える場合、**「上位計算をPi、リアルタイム制御を専用回路に任せる階層構成」**が最も現実的で安定します。Pi単体でのLinuxリアルタイム制御は1kHz以上を安定して回すのが難しいためです。

以下に、用途別の2つの構成案を示します。

---

## 構成案A：小型実験機・DIY向け（最も安価）

ステッピングモータを使い、Piから直接制御します。精度は中程度ですが、コストが抑えられます。

### ハードウェア構成

| 部位 | 部品例 |
|------|--------|
| **コントローラ** | Raspberry Pi 4（8GB推奨）または Pi 5 |
| **GPIO拡張** | CNC Shield v3.0（Arduino Uno形状）+ Raspberry Pi GPIO接続アダプタ、または専用HAT |
| **モータ** | NEMA23 ステッピングモータ ×6（保持トルク 1.26Nm程度） |
| **ドライバ** | TB6600 または DM556 ステッパードライバ ×6 |
| **電源** | DC 24V 15A スイッチング電源（モータ用）+ DC 5V 3A（Pi用） |
| **通信** | USB（キーボード・Wi-Fi設定用）、GPIOからのパルス/ディレクション信号 |
| **センサ** | リミットスイッチ ×12（各脚上下）、オプションでロータリエンコーダ |
| **安全** | 緊急停止スイッチ → リレーでモータ電源遮断（Pi経由ではなくハード回路） |

### 接続イメージ

```
Raspberry Pi
   └─ GPIO ─┬─ PUL/DIR信号 ─→ ステッパードライバ×6 ─→ ステッピングモータ×6
            ├─ リミットスイッチ入力（×12）
            └─ E-Stop入力（ハード回路と並列監視）
```

### ソフトウェア構成

- **OS**: Raspberry Pi OS（64bit）
- **IK・軌道生成**: Python（NumPy）で実装
- **GPIO制御**: `pigpio` ライブラリ（ハードウェアPWMが使えて比較的安定）
- **UI**: FlaskまたはStreamlitでWebブラウザから姿勢指令
- **通信**: オプションでMQTTまたはWebSocketで外部PCから指令受信

### 制御ループ

1. Pythonで目標姿勢から6脚の目標長さを計算（IK）
2. 現在長から差分を求め、各モータのパルス数に変換
3. `pigpio`で各軸に非同期パルス列を出力（S字加減速はソフトウェアで補間）
4. リミットスイッチ入力をポーリングまたは割り込みで監視

### 課題
- 6軸同時に滑らかな補間をPi単体で回すのは負荷が高い
- ステッピングモータは開ループのため、負荷変動で**失調（ずれ）**するリスクあり
- 標準Linuxカーネルではタイムジッターが発生し、動作がわずかにガタつく可能性あり

## 構成案B：中級・高精度向け（推奨）

Piを「指令生成・通信・UI」の上位機として使い、**リアルタイム制御は専用マイコンまたはモーションコントローラ**に任せます。

### ハードウェア構成

| 部位 | 部品例 |
|------|--------|
| **上位コントローラ** | Raspberry Pi 4/5（IK計算、Web UI、データロギング） |
| **下位コントローラ** | **Arduino Mega** + **RAMPS 1.4**（Marlinファームウェア改造）、または **Teensy 4.1**、**ESP32-S3** |
| **モータ** | 閉ループステッピングモータ（エンコーダ付き）×6、または低価格ACサーボ |
| **ドライバ** | 閉ループステッパードライバ ×6、またはサーボドライバ |
| **通信Pi↔下位** | USBシリアル、UART、またはCANバス（ESP32の場合） |
| **センサ** | リミットスイッチ、オプションでムーバー側IMU（MPU6050/BNO055、I2C接続） |
| **電源** | DC 24V/36V 大容量（モータ用）、DC 5V（Pi・マイコン用） |
| **安全** | 独立したE-Stopリレー回路 |

### 接続イメージ

```
Raspberry Pi（上位）
   ├─ USB ─→ Arduino Mega / Teensy 4.1（下位リアルタイム制御）
   │            └─ パルス/アナログ信号 ─→ モータドライバ×6 ─→ モータ×6
   ├─ I2C ─→ BNO055（ムーバーIMU、オプション）
   └─ Wi-Fi/Ethernet ─→ PCやジョイパッドから指令受信
```

### ソフトウェア構成

| 層 | 役割 | 技術 |
|----|------|------|
| **上位（Pi）** | IK計算、軌道計画、Web UI、ログ保存 | Python + NumPy + Flask/Streamlit |
| **通信** | 目標脚長または目標姿勢の送信 | USBシリアル（JSONまたはバイナリプロトコル）、ROS |
| **下位（マイコン）** | 1kHz〜10kHzの位置制御、補間、E-Stop処理 | Arduino（C++）、FreeRTOS、またはPlatformIO |

### 制御フロー

```
PC/ジョイパッド
   ↓ （目標姿勢を送信）
Raspberry Pi
   → IK計算 → 6軸の目標脚長・目標速度を生成
   → 10ms周期で下位マイコンにパケット送信（「脚1: 150.2mm, 速度: 20mm/s」など）
Arduino/Teensy
   → 受信した目標値に基づき、各軸のPID制御・S字加減速を1kHzで実行
   → リミットスイッチ・E-Stopを直接監視し、異常時は即停止
```

## 構成案C：LinuxCNCを使う本格派

Pi上で**LinuxCNC**（実機制御用のオープンソースCNCソフト）を動かし、専用の**Mesaインターフェースボード**を使ってGPIOをリアルタイム拡張します。

| 部位 | 部品 |
|------|------|
| **Pi** | Raspberry Pi 4 + Raspberry Pi OS with LinuxCNC |
| **I/Oボード** | Mesa Ethernet/SPiインターフェース（例: 7C81などPi用HAT） |
| **モータ** | サーボまたはステッピング |
| **特徴** | Gコードで動作可能、産業級の補間制御が使える |

ただし、スチュアートプラットフォームのIKをLinuxCNCに組み込むには**HALコンポーネントのカスタマイズ**が必要で、ハードルが高いです。

---

## Raspberry Pi構成の選び方

| 目的 | 推奨構成 |
|------|----------|
| **とにかく安く試したい** | 構成A（Pi + TB6600 + ステッピング） |
| **ある程度の精度・滑らかさが欲しい** | **構成B（Pi + Teensy 4.1 + 閉ループステッパー）** ← 最もバランスが良い |
| **産業級の信頼性が必要** | 構成C（LinuxCNC + Mesa）またはPiを諦めてTwinCAT |

---

## 実装上の注意点（Pi特有）

1. **電源の分離**: Piの5V系とモータの24V系は完全に分離。モータのノイズでPiがリセットするため、フォトカプラで絶縁することを推奨します。
2. **リアルタイム性**: PiのGPIOから6軸同時に滑らかなパルスを出すのは限界があります。下位マイコンを挟む構成Bが現実的です。
3. **熱対策**: Pi 4/5は負荷時に発熱します。ヒートシンクまたはファンを必ず装着してください。
4. **SDカードの寿命**: 頻繁なログ書き込みでSDカードが破損するため、USB SSDブートまたは工業用microSD（高耐久）を使用してください。

予算や目標とする積載重量・可動速度が決まっていれば、モータのトルク選定や電源容量の計算まで具体的に案内できます。
